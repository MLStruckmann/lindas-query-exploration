THE PROBLEM
================================================================================

Filtered SPARQL queries returned 0 results even though data existed:
  
  Query: FILTER(?period = "2024")
  Result: 0 rows (WRONG!)
  
Expected: Should return 48,620 observations from 2024

================================================================================
ROOT CAUSE IDENTIFIED
================================================================================

The 'period' field is stored as xsd:gYear datatype (not a plain string).

Direct string comparison failed:
  FILTER(?period = "2024")  ❌ Datatype mismatch

================================================================================
THE FIX
================================================================================

File: sparql_extractor.py
Line: 86

Changed from:
  year_filter = f"FILTER(?period IN ({year_list}))"

Changed to:
  year_filter = f"FILTER(STR(?period) IN ({year_list}))"

The STR() function converts xsd:gYear to string before comparison.

TECHNICAL LEARNING
================================================================================

Key Insight: SPARQL datatype handling is critical for filters

When filters fail, check datatypes:
  SELECT DISTINCT ?period (DATATYPE(?period) as ?datatype)
  
Common SPARQL datatypes requiring special handling:
  - xsd:gYear      → Use STR() or typed literal "2024"^^xsd:gYear
  - xsd:date       → Use date functions or STR()
  - xsd:dateTime   → Use datetime functions or STR()
  - xsd:integer    → Use numeric comparison or STR()
